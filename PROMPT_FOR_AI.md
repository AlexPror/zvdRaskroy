# 🤖 ПРОМПТ ДЛЯ AI-АССИСТЕНТОВ

## Копируйте этот промпт в начало любого чата про КОМПАС-3D

---

```
Я работаю с автоматизацией КОМПАС-3D через Python и win32com API.

КРИТИЧНЫЕ ПРАВИЛА (проверено на практике):

1. ВСЕГДА используй pythoncom.CoInitialize() в начале и CoUninitialize() в конце

2. Для сохранения marking (обозначения) деталей ОБЯЗАТЕЛЬНА последовательность:
   part.marking = "новое"
   part.Update()
   part.RebuildModel()
   iDocument3D.RebuildDocument()
   api7.ActiveDocument.Save()
   api7.ActiveDocument.Close(True)
   Без этой последовательности изменения НЕ сохранятся!

3. Экспорт чертежей в BMP/PNG:
   - СНАЧАЛА: doc2d.ksRebuildDocument() и time.sleep(2)
   - ЗАТЕМ: active_doc.Save()
   - ЗАТЕМ: SaveAsToRasterFormat(path, params, format_code)
   - format_code передается ТРЕТЬИМ параметром! (1=BMP, 2=PNG)
   - Без Rebuild → пустой файл!

4. Экспорт в DXF:
   - Используй doc2d.ksSaveToDXF(path)
   - НЕ используй SaveAs(".dxf") - создает ZIP!

5. Гиперссылки ЗАЩИЩЕНЫ:
   - linkDocName/linkVarName нельзя изменить программно
   - API блокирует создание гиперссылок
   - Решение: вычислять переменные в приложении и обновлять в сборке + деталях

6. Детали в сборке:
   - Получать через iPart.GetPart(index), а не GetParts()
   - Если деталь используется несколько раз - обновлять ВСЕ экземпляры через сборку

7. Группировка деталей:
   - Одинаковое имя детали → одинаковый номер в обозначении!
   - Сначала сгруппировать по именам, затем присвоить номера

8. Всегда добавляй time.sleep():
   - После Open: 2 сек
   - После Rebuild: 1 сек  
   - После Save: 1 сек
   - После Close: 1 сек

9. Файлы .m3d, .a3d, .cdw - это ZIP архивы
   - Но данные внутри бинарные!
   - Прямое редактирование опасно

10. API версии:
    - API 5 - для 3D, переменных, rebuild
    - API 7 - для документов, открытия/закрытия
    - Часто нужны ОБА одновременно

ПОДРОБНАЯ БАЗА ЗНАНИЙ: См. файл KOMPAS_API_KNOWLEDGE_BASE.md
```
